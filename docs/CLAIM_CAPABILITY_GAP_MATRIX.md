# Claim-to-capability gap matrix

**Status:** in_progress
**Truth review:** 2026-07-22
**Rule:** ambitious claims remain product requirements, but a public surface may say
`implemented` only after the linked acceptance evidence passes for a versioned build.
Local primitive demonstrations, mutable checksums, design intent, and source presence
do not satisfy an end-to-end capability gate.

## Promotion rule

A claim can move from `not_implemented`, `demo_only`, or `partial` to
`implemented` only when all of the following exist together:

1. A version-pinned implementation path, not only a primitive or fixture.
2. Deterministic positive, negative, adversarial, recovery, and interoperability tests.
3. A documented threat/failure model and explicit residual limitations.
4. Production observability that measures reliability without contradicting privacy.
5. Artifact-bound release authentication and a reproducible command transcript.
6. Public copy generated from the same status record, with CI rejecting stale or
   stronger wording.
